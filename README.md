# Бадимка: Владыка Королевства

Изометрический средневековый сити-билдер. Vanilla JavaScript + Canvas, сборка через Vite.

## Структура проекта

```
badimka/
├── index.html               # точка входа (минимальный HTML)
├── package.json             # зависимости (vite)
├── vite.config.js           # настройки сборки
├── public/
│   ├── sprites/             # PNG-ассеты построек (опционально, можно класть свои)
│   └── audio/               # звуки и музыка (позже)
└── src/
    ├── main.js              # старт игры
    ├── style.css
    ├── config.js            # все константы (HW, HH, MW, T_*, PALB)
    ├── data.js              # BUILD, TECHS, QUESTS, имена жителей
    ├── utils.js             # clamp, mulberry32, shade, fbm
    ├── globals.js           # namespace G — всё общее изменяемое состояние
    ├── store.js             # localStorage обёртка
    ├── map.js               # генератор карты
    ├── sprites.js           # фабрики процедурных спрайтов + чанки + мини-карта
    ├── customSprites.js     # загрузчик PNG-ассетов (заменяет процедурку)
    └── game.js              # state + симуляция + рендер + ввод + UI
```

## Установка (один раз)

Нужен **Node.js версии 20+**. Скачать с [nodejs.org](https://nodejs.org).

После установки Node, в папке проекта:

```bash
npm install
```

Это установит Vite и его зависимости в папку `node_modules/`. Делается один раз.

## Команды

### Разработка с автоперезагрузкой

```bash
npm run dev
```

Откроется браузер на `http://localhost:5173`. Любая правка `.js` или `.css` — страница автоматически обновится без перезагрузки. Это основной режим для разработки.

### Сборка финального файла

```bash
npm run build
```

Появится папка `dist/` — это и есть готовая игра. В ней:

```
dist/
├── index.html
└── assets/
    ├── badimka.js       (~130 КБ, всё в одном файле)
    └── index.css        (~6 КБ)
```

### Предпросмотр собранной версии

```bash
npm run preview
```

Запускает локальный сервер для папки `dist/` чтобы проверить как работает финальная сборка.

## Раздача игры друзьям

1. Запустить `npm run build`
2. Запаковать папку `dist/` в zip
3. Отправить другу
4. Друг распаковывает архив и **открывает `index.html` двойным кликом** — игра работает в браузере офлайн, без интернета

Размер архива ~50 КБ в gzip. Чтобы игра работала без http-сервера, в `vite.config.js` уже выставлено `base: './'` (относительные пути).

## Загрузка PNG-спрайтов

В игре есть два способа подменить процедурную графику на нарисованные ассеты:

**Способ 1 (рекомендуемый) — через UI:**
1. Открыть игру
2. Меню → ❓ Помощь
3. В самом низу — кнопка «📁 Выбрать PNG-файлы»
4. Выбрать сразу все PNG (можно несколько)
5. Игра распознает имена и подменит соответствующие здания

**Способ 2 — через папку `public/sprites/`:**
1. Положить PNG в `public/sprites/`
2. Запустить `npm run dev` (или после build — `npm run preview`)
3. Игра автоматически подхватит PNG из этой папки

Имена файлов:
- Дома: `house_lvl1.png`, `house_lvl2.png` ... `house_lvl7.png` (любой суффикс типа `_hovel`, `_v2` работает: `house_lvl1_hovel.png`)
- Здания: имя должно начинаться с ID — `tavern.png`, `church.png`, `townhall.png`, `farm.png`, `mill.png` и т.д. Полный список ID можно глянуть в `src/data.js` — объект `BUILD`
- Природа: `tree_oak.png`, `tree_pine.png`, `rock.png`

PNG должны быть **с прозрачным фоном** (alpha-channel), один объект на файл, минимум 1024×1024.

## Архитектурные заметки

- Всё мутируемое состояние игры собрано в одном namespace `G` (см. `globals.js`) — это упрощает доступ из разных модулей без сложных импортов let-переменных
- `game.js` — большой файл (~1800 строк), в нём вся симуляция + рендер + UI. В будущем его можно дальше разбить на отдельные модули, сейчас оставлен цельным для скорости работы
- Процедурная графика и PNG-ассеты могут сосуществовать. Если PNG для здания не найден — рисуется процедурно. Можно подменять постепенно по мере генерации ассетов
- Сохранения хранятся в `localStorage` браузера. **Важно:** localStorage привязан к origin (URL), поэтому игра запущенная через `npm run dev` (http://localhost:5173) и игра открытая из dist/index.html (file://) будут иметь разные сохранения. Используй экспорт/импорт сейва файлом для переноса
