# Бадимка: Владыка Королевства

Изометрический средневековый сити-билдер / экономическая стратегия в одном HTML-файле (vanilla JS + Canvas, без сборки, без зависимостей).

## 1. Что это

Игрок строит и развивает средневековое поселение: добывает ресурсы, строит здания (жильё, производство, оборона, культура), управляет горожанами (которые сами ходят, работают, женятся, болеют, эволюционируют дома), исследует технологии, выполняет квесты, торгует караванами, отбивается от набегов и восстаний, ведёт героя-старосту через систему уровней.

Визуальный стиль: тёплая изометрия в духе Settlement Survival / Travellers Rest — процедурная генерация спрайтов (не PNG-ассеты), направленное закатное освещение, кирпичная кладка, черепица, цветочные ящики, фонари, виньетка.

Игра полностью клиентская, одиночная, сохранения — в localStorage браузера, с возможностью экспорта/импорта save-кода.

## 2. Технический стек

- **Один HTML-файл** (~3400 строк), всё внутри: HTML-разметка UI, CSS, JS-логика и рендер
- **Canvas 2D** — основной рендер (`#c`), мини-карта (`#mm`)
- Никаких сторонних библиотек, фреймворков, бандлеров. Открывается напрямую в браузере
- Сохранение: `localStorage` (префикс `bvk-save-`), плюс сериализация в текстовый код для экспорта/импорта между устройствами
- PRNG: `mulberry32` (детерминированная генерация по seed — карта, спрайты деревьев/построек воспроизводимы)

## 4. Графическая система (важно для дальнейшей работы)

### Текущий подход — процедурная генерация
Все спрайты зданий, деревьев, людей рисуются кодом через `mkIso()` — фабрику, которая создаёт offscreen-canvas, рисует изометрический полигональный объект через набор примитивов (`box`, `roofG`, `wall`, `diam`, `cyl`, `winr`, `door` и т.д.) и кэширует результат как картинку. Базовый тайл сейчас **128×64px** (учетверённый от исходных 32×16), внутренний рендер идёт через `ctx.scale(4,4)` для детализации.

Реализовано (этого добиваться повторно не нужно — уже готово):
- Тёплое направленное "закатное" освещение (`warm()` — ЮЗ грани тёплые/светлые, ЮВ — холодные/тёмные)
- Процедурные текстуры: кирпичная кладка со смещением рядов, доски с волокнами и сучками, чешуйчатая черепица (tile/slate) с бликами
- Детальные окна (рама, крестовина, светящееся стекло, подоконник, открытые цветные ставни с петлями)
- Детальные двери (доски, петли, ручка, каменный порог)
- Уютные мелочи: цветочные ящики, кованые фонари с сиянием, поленницы дров, мощёные дорожки
- Медные водостоки по кромкам крыш
- Орнаменты: вывеска-кронштейн у таверны, витраж с крестом у церкви, герб с короной у ратуши
- Декорации травы (цветочки, кустики), субпиксельные обводки полигонов для сглаживания, виньетка экрана

### Потолок процедурного подхода
Дальнейшее повышение разрешения **не даст качественного скачка** — детализация ограничена не пикселями, а количеством геометрии, которую можно нарисовать кодом. Реалистичный потолок достигнут — между уровнем Settlement Survival и Travellers Rest.

### Если нужен скачок до уровня Anno/Cossacks/StarCraft
Это требует **смены подхода**: готовые спрайты (PNG с прозрачностью) вместо процедурки — нарисованные художником, купленные (CraftPix, Unity Asset Store, itch.io/Kenney) или сгенерированные через AI (Midjourney/SD с промптами на изометрию + remove background). Код заменяет `mkIso(...)` на `drawImage(loadedSprite, ...)` — остальная архитектура (симуляция, AI, экономика) не меняется.

## 5. Игровые системы

### Ресурсы
Дерево, камень, глина, железная руда, уголь, доски, кирпич, инструменты, еда (зерно/рыба/мясо/хлеб/сыр/вино — суммируются в `foodStock`), ткань/одежда, украшения, книги, золото.

### Постройки (44 типа в `BUILD`)
Категории: жильё (дома 7 уровней эволюции), еда (ферма/огород/пастбище/рыбак/охотник/мельница/пекарня/сыроварня/виноградник), сырьё (лесопилка/каменоломня/глиняный карьер/рудники), переработка (лесопилка→доски, столярка, кузница, оружейная, ткацкая/портной, ювелир, скрипторий), инфраструктура (колодец, рынок, дороги), культура (церковь, школа, больница, таверна, театр, ярмарка), оборона (казарма, башня, стена, арсенал), администрация (ратуша, налоговая, суд, торговый пост, дворец).

### Горожане
Каждый — объект с домом, работой, координатами, целью движения. AI: идут на работу утром, домой вечером, посещают рынок/таверну/церковь по потребностям. Дома эволюционируют 7 уровней при выполнении требований соседства (`HREQ`) — рынок, церковь, вода, еда и т.д. рядом.

### Герой-староста
Уровни через получение опыта (`giveXp`), титулы по уровню (`TITLES`), участвует в бою.

### Технологии (`TECHS`)
Модификаторы производства/защиты, разблокируются через очки исследований.

### Квесты (`QUESTS`)
Цепочка целей с проверкой условий (`questCheck`), продвигают сюжет/прогрессию.

### События и угрозы
Случайные события (`randomEvent`), чума (`startPlague`/`plagueTick`), пожары (`startFire`/`fireTick`), набеги (`spawnRaid`), восстания (`spawnRebels`), бой юнитов (`combat`).

### Циклы
`daily()` — ежедневный тик (производство, потребление еды, счастье, рост населения), `yearly()` — годовые события, `seasonIdx()` — 4 сезона по 12 дней.

### Сохранение
`serialize()`/`restore()` — полный snapshot состояния (карта, здания, жители, ресурсы, технологии, квесты). Автосейв в localStorage + ручной экспорт/импорт текстового кода save.

## 6. Известные ограничения / на заметку

- Один файл — удобно для распространения, но затрудняет совместную разработку. При масштабировании стоит подумать о разделении на модули (хотя бы логически закомментированными секциями, что уже частично есть)
- Процедурная графика — основной потолок визуального качества. Любые запросы "сделай красивее" без смены подхода на спрайты дадут убывающую отдачу
- Игра не локализована (весь текст на русском, хардкод)
- Нет звука/музыки
- Десктоп-ориентирована (мышь), но есть базовая поддержка тач (pinch-zoom, drag)

## 7. Инструменты разработки (вспомогательные файлы, не часть игры)

При разработке использовались Node.js-скрипты для визуальной проверки без браузера:
- `viz.js` — рендерит сцены города на разных масштабах через `@napi-rs/canvas`
- `showcase.js` — крупные планы отдельных зданий (сетка 3×3)
- `zoom.js` — рендер одного/нескольких зданий в натуральном масштабе 1:1
- `smoke.js` — дымовой тест: симулирует N дней игры через DOM-стабы, проверяет что симуляция/UI/снос не падают с исключениями

Эти скрипты можно пересоздать по необходимости — они не входят в финальный `badimka.html`, но полезны для CI/проверки правок.

## 8. Текущий статус

Файл стабилен, все smoke-тесты проходят. Графика на потолке процедурного подхода (тайл 128×64px, ×4 от исходного разрешения). Готов к переносу в проект для дальнейшей разработки — следующий крупный шаг, если потребуется AAA-визуал — переход на спрайт-ассеты (см. раздел 4).
